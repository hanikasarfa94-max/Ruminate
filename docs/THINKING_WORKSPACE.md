# 让问题继续生长

这一版围绕两种体验：把研究结论多推敲一层，以及在不同主题之间发现联系。
管理页仍然只有想法、资料、输出三个入口。

## 反刍卡片

问题标题下面先展示一个具体的联系或张力，点开后有一至三个递进的追问。
例如“动作都完成了，为什么结果仍不理想”，可以先回想一次具体经历，
再区分执行、判断和目标，最后考虑这条经验在什么条件下会失效。
不要求每张卡片都设计一个完整实验，也不替用户预先回答。

引导由当前 Codex 读取原文后写入，保留 `host_model` 来源及已有引用 ID。
同一问题可追加新的引导版本，原始问题、引用和输出不会被覆盖。
“我的思考”保存用户输入；AI 补充单独标明来源。两者都不会自动变成已确认观点。

“沿着这条想法”展示有具体理由的关联，另一端显示反向联系。
关联来自模型的解释，当前实现不把关键词重合包装成语义搜索。
打开想法会将有范围限制的引用、最新引导和最近两段思考交给宿主上下文；
“继续聊这条”沿用宿主对话，支持时先放入可编辑输入框。

## 自动整理主题

Codex 先读内容，再用 `suggest_topic` 推荐已有主题。确有不同的研究范围时才创建主题。
资料分类绑定读取时的版本；想法新增次级主题，保留原主题。
一个想法可以同时用于不同主题的研究和输出。

已授权自动整理时使用 `auto_apply=true`。其他情况保留为待采用建议。
“整理主题”展示对象、主题、推荐理由及采用或撤回操作。
用户略过或撤回的建议不会因下一次运行换了请求 ID 就再次出现；
同一资料出现新版本后可以重新评估。撤回只移除这次自动添加的关联，保留手动选择。
历史输出保存当时的主题关联，之后撤回也仍能核对原修订。

页面的“请 Codex 整理”将请求带入当前宿主对话。每天的整理由已有 Codex 定时任务执行；
页面自身没有后台模型进程，也不需要模型 API Key。

## 思考足迹

首页展示最近十二周、按北京时间划分的活动。计入手动写下的想法、个人思考记录、
主动反馈；同一想法同一天的多次反馈合并为一次。
后台生成、导入、打开页面和候选曝光不计入。点击有活动的日期，可以回到当时的想法。
这里没有连续打卡奖励或补齐空白日期的目标。

## 实现与兼容

- `Application.thinking`：引导修订、个人思考、明确关联与活动聚合。
- `Application.organization`：分类建议、采用、撤回、版本检查与审计。
- schema 7 添加四张表及来源分类的归属字段；旧迁移不变。
- CLI、MCP、内嵌页面与 HTTP 预览共用服务；备份包含新增记录。
- 每页思考记录 20 条，分类建议 25 条；日期详情显示最近 100 条并提示截断。
- 原生宿主可用范围与协议测试分别记录在 `EVALUATION.md`。

## 参考

借鉴的是组织思路，未复制这些产品的代码或素材：

- [flomo：笔记热力图](https://help.flomoapp.com/advance/notes-graph.html)：按日期回到记录。
- [flomo：相关笔记](https://help.flomoapp.com/basic/xgbj.html)：以当前内容为线索继续探索。
- [Obsidian：反向链接](https://obsidian.md/help/plugins/backlinks)：从被引用的一端回到上下文。
- [Logseq 文档](https://github.com/logseq/docs/blob/master/pages/tutorial.md)：小块记录与双向引用。

Ruminate 的取舍是保留可追溯关联和日常回看，先不加入全屏知识图谱或复杂笔记树。
