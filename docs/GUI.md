# Ruminate 统一管理页

从 Codex / ChatGPT 插件栏打开 Ruminate，默认进入“想法”，导航顺序为“想法 / 资料 / 输出”。三类内容共用主题筛选、搜索和排序，列表每页 25 条，条数来自实际总量。点击内容在同一区域阅读，返回保留筛选、页码与位置。

页面通过 MCP Apps 的 `ui/initialize` / `tools/call` 读取同一份本地资料库。无需另开网页服务；CLI、Codex 与定时反刍保存的内容都会出现在这里。

## 日常使用

1. **资料**：添加网页、PDF 或笔记；搜索标题与当前版本原文。阅读时可查看历史版本、打开 PDF 页图，从某段原文记下带引用的想法。
2. **想法**：查看资料观点、问题、推测和假设。AI 提出的内容标注“AI 提出”，手动记录与用户明确确认的观点分别标注。用户确认观点可查看记录来源和关联想法。
3. **待回看**：自动反刍生成的问题经 `tick` 入队后在这里出现。列表显示问题、回看理由和引用数量；详情展示下一步与精确出处。点引用进入保存时的原文，再返回想法。
4. **反馈**：“有启发”记为已回看，“稍后再看”安排到 7 天后，“略过”关闭本次建议。分别在“稍后”“已处理”中查找。一个想法有多个回看问题时，处理一个后，剩余问题仍会保留。
5. **输出**：创建项目、生成有引用的提纲、查看历史版本和导出 Markdown；点击引用返回原文。

“待回看”是完整的到期列表，按想法去重；它不受每日主动推荐 3 条或同来源限频影响。打开列表不会记录曝光、改变用户观点或自动确认建议。主动推送仍使用原有 `present` 限频机制。

界面返回前台时检查更新，保持打开时每分钟检查一次；只有数据变化才刷新列表，阅读详情、输入和表单操作期间保留当前内容。也可点击工具栏右侧的刷新按钮。调度时间由宿主 Scheduled 管理，详情见[自动反刍](AUTO_REFLECTION.md)。

## 嵌入与预览

界面适配宿主深浅色主题和容器宽度，保持一个主滚动区。资料和 PDF 图片通过 MCP 返回；页面不访问 localhost 或外部资源。“在对话中继续”仅在宿主支持时出现，传递当前选中的想法和精确出处。

前端开发时可启动同一界面的 HTTP 预览：

```bash
uv sync --locked
uv run ruminate ui
# 指定已有资料库：
uv run ruminate --data-dir /absolute/path/to/data ui
```

服务只监听 127.0.0.1，并使用同源检查和会话令牌保护写入。插件安装与入口验证见[Codex 接入](CODEX_MCP_UI.md)。

## 当前范围

主题下拉中选择一个主题后，点击“编辑当前主题…”可修改名称和研究问题。资料阅读页的“编辑资料”支持修改显示名称、选择多个主题、取消归类，也可直接新建主题。重新导入后会保留自定义名称；“恢复原始标题”重新使用当前版本的标题。

主题 ID 和 slug 保持稳定，已有想法与输出仍归属于原主题。资料换主题只调整资料分类，原文、历史版本、证据定位及已生成提纲均保留。

主题列表最多显示 50 项；资料编辑器额外保留已关联主题和本次新建主题。归档和批量整理尚未提供。

文件选择器只提交选中文件，支持 PDF、Markdown、TXT 和 HTML，默认上限 20 MiB。URL 只在提交导入后抓取，`RUMINATE_NETWORK_MODE=off` 可关闭抓取。

Markdown 优先使用宿主下载能力；未开放时提供完整文本复制。连同原件导出可使用 CLI export 或备份。

内嵌组件和插件栏入口已通过人工验收。新版统一管理页的完整交互已通过独立浏览器协议宿主连接真实 stdio MCP 验证，包括反馈、PDF、引用、导出和 390px 窄窗口；原生客户端的完整点击流程单独验收。结果见[测试记录](evidence/browser-workflow.json)。

## 0.5.1 控件与宿主对话

主题、排序、版本和表单下拉使用统一的 combobox/listbox 样式。支持方向键、Home/End、文字定位、Enter、Escape、Tab 与外部点击收起；弹层根据窗口剩余空间向上或向下展开。在表单内按 Escape 先关闭下拉，保留表单。文件选择使用页面按钮并展示文件名；“暂不归入主题”与列表的“全部主题”分别表示保存方式和筛选范围。

支持 `ui/update-model-context` 时，列表、想法、资料、PDF 当前页与输出提供有限的当前阅读上下文。想法包含模型/人工来源、类型、最多五处引用及版本/片段定位；查看引用和返回会替换上下文。更新顺序串行，单次不超过 24 KiB。用户在宿主移除关联后，同一选中内容不会自行恢复；未提交的表单不进入上下文。

打开一条想法后，可以在宿主对话中问“这条有哪些反例？”或“下一步优先补什么证据？”。支持 `openai/message` 扩展时，“继续聊这条”通过 `send:false` 填入可修改的草稿；只有用户发送后才开始对话。未提供该扩展的宿主保留明确点击的“在对话中继续”操作。不支持上下文接口的宿主，只在该操作时带入选中内容。

接口依据：[OpenAI 扩展规范](https://github.com/openai/mcp-extensions/blob/main/docs/spec.md)、[MCP Apps UI 指南](https://developers.openai.com/plugins/build/chatgpt-ui)。全局插件入口使用它自己的配套聊天。当前版本的协议模拟宿主已验证上下文切换、返回、移除和草稿；新版原生桌面的聊天效果仍以实际页面为准。[本轮验收](evidence/browser-workflow.json)


## 导出格式

新生成的 Markdown 使用 format 2，按想法类型整理内容并保留原文引用。已有 format 1 草稿保持原文，继续支持历史版本读取与导出。
