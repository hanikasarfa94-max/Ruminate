# Codex 定时反刍

2026-11-17。定时任务由宿主调度，Codex 负责阅读和推理，Ruminate 负责保存资料、引用、问题、队列及反馈。沿用当前登录的 Codex，无需为 Ruminate 增加模型 API 客户端。

## 每轮工作

1. 读取本地资料版本、主题、已有问题、输出修订和最近反馈；与上次运行记录比较。资料、目标、用户反馈均未变化，也没有到期的有效后续事项时，结束本轮。
2. 选择最多三个值得推进的问题。优先寻找跨材料的联系、被忽略的适用条件、可验证的差异和对现有提纲的具体改进。旧问题的同义改写不算新建议，资料少时可以零条。
3. 先读原文再保存问题和精确引用。用 save_reflection_guide 点出联系或张力，给一至三个递进追问及有理由的想法关联；新问题和旧问题引导更新合计最多三条。
4. 使用现有 record_claim / link_evidence，或相同 Application 方法，将问题和原文关系写入本地库。问题使用 question / host_model，引用通常使用 mentions。同一操作重试复用 request_id。
5. 对涉及主题执行 ruminate tick，将新问题接入反刍队列。后台生成不调用 present，也不代替用户写反馈。
6. 在配置的运行目录保存输入版本、建议、引用、claim/review ID 与结果。完成后重新记录状态，避免把本轮自己的新增误认为下一轮的新输入。

模型负责判断语义是否重复；现有请求幂等机制负责重复提交。输入有上限或返回被截断时，应缩小主题与材料范围，不声称已审阅全部资料。

## 内容整理

每轮还可以检查最多十二个未整理对象。先阅读内容，优先沿用已有主题，
用 suggest_topic 保留分类理由。明确授权自动整理时追加分类，其他情况留为待采用建议。
不重复同一内容下已略过或撤回的建议，不因分类变化重新生成同义问题。
个人思考、分类积压和缺少引导的旧问题都纳入输入比较；未处理完的范围记入运行记录。
引导、分类和后台问题都不增加思考足迹的计数。详情见 [思考工作台](THINKING_WORKSPACE.md)。

## 页面承接

管理页保持“想法 / 资料 / 输出”三个入口。新增建议归入“想法 → 待回看”，列表展示问题和简短推荐理由，详情展示递进追问、个人思考与原文。提供“在对话中继续、有启发、稍后再看、略过”，后续运行读取已保存的反馈调整选题。

定时设置由宿主 Scheduled 管理。页面可以展示真实的最近生成时间、建议数量和手动生成入口；宿主未提供任务状态读取接口时，不根据本地旧记录显示“正在运行”等实时状态。

0.5.0 已实现统一管理页。建议经 `record_claim` / `link_evidence` 和 `tick` 保存后直接进入“想法 → 待回看”，无需迁移。该列表读取全部到期且未关闭的回看事项，按想法去重；不调用 `present`，不消耗主动推送额度。列表显示问题、推荐理由、实际保存时间与出处，详情提供下一步及反馈。定时任务不再需要读取旧版“研究”页面。

AI 建议标注“AI 提出”；现有数据的 `host_model` 来源也包含手动 Codex 会话写入，因此界面不把所有 AI 问题都声称为自动运行产物。页面返回前台或保持打开每分钟检查本地变化，输入和阅读详情期间不打断操作。

## 设置与验证

在自己的 Codex 客户端创建定时任务，指定项目、资料库、运行目录和时区，例如每天
上午 9 点。使用 [提示词模板](auto-reflection-prompt.md)，先手动执行一轮，确认建议、
精确引用和反馈能从同一个工作台读回，再观察实际定时触发。

Ruminate 已验证当前会话中的读取、建议保存、引用核对和队列接入路径。
定时运行依赖使用者自己的宿主设置；安装源码不会自动创建任务。运行记录保存在
自己的本地目录，不需要提交到仓库。内核没有新增云模型客户端。

## 宿主条件

本地文件任务需要电脑开机、桌面应用运行且目录可访问。执行权限沿用宿主任务设置。网页定时任务不直接持有本机目录。[官方 Scheduled tasks 文档](https://learn.chatgpt.com/docs/automations)

其他人安装时，配置自己的资料库路径并创建本地任务；个人自动化不会随插件源码自动启用。运行提示词模板见 [auto-reflection-prompt.md](auto-reflection-prompt.md)。
